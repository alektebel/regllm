# DQC Eval Harness

Stress-test the **DQC agent** (`api/routers/dqc.py` + `training/dq/`) against a
complete 7-layer PD & LGD estimation database built from the BASILEA table, and
**detect where the model is deficient** — broken down by industry data-quality
dimensions (DAMA / ISO 8000 / BCBS 239).

```
SAS pipeline (7 layers) ──► CICLOS_CALIBRADOS schema ──► data_dictionary.md
        │                          │
        └── corrective fixes      └── defect_catalog.py (26 ground-truth defects, 8 DQ dims)
                                   │
        generate_db.py ──► clean SQLite  +  per-defect trap SQLite (mutation testing)
                                   │
                             eval_harness.py
                                   │
              ┌────────────────────┼────────────────────┐
              ▼                    ▼                    ▼
         --selftest          --sql FILE           --agent URL
       (oracle audit)    (free-form recall)   (targeted per-defect)
                                   │
                       per-dimension recall  →  DEFICIENT flags
```

## Files

| Path | Role |
|---|---|
| `sas/ciclos_calibrados_pipeline.sas` | 7-layer PD+LGD pipeline (L0 sources → L7 ECL/RWA), corrective fixes, documents the planted defects D01–D25. |
| `data_dictionary.md` | Final-table schema + per-field description, lineage layer, regulatory ref. |
| `defect_catalog.py` | 26 ground-truth defects across 8 DQ dimensions, each with an `oracle_sql` + a `mutate(row)`. |
| `generate_db.py` | Builds a clean SQLite DB (all invariants hold) + one trap DB per defect. |
| `eval_harness.py` | Self-test, free-form coverage, agent-targeted scoring, per-dimension deficiency report. |
| `example_checks.sql` | A sample check file to exercise coverage mode. |
| `data/` | Generated `clean.db` + `trap_<id>.db` (written by `generate_db.py`). |

## The 7 layers (≥7-hop lineage)

`L0` BASILEA/CONTRATOS/CICLOS/COLATERALES → `L1` staging coercion → `L2` fusion
enrichment → `L3` BASILEA OR_EAD join (dedup fix) → `L4` PD calibration/floors
→ `L5` LGD downturn/floors/MoC → `L6` EAD/CCF → `L7` ECL+RWA+IFRS-9 stage. The
deepest fields (`ECL`, `RWA`) read inputs from every upstream layer.

## The 8 data-quality dimensions covered

Source: Wikipedia *Data quality* (DAMA dimensions), ISO 8000, and BCBS 239
principles P3–P5 (accuracy & integrity, completeness, timeliness).

| Dimension | Defects | BCBS 239 |
|---|---|---|
| consistency | D01–D09, D11–D13, D15, D16 | P3 |
| validity | D19, D20 (+decoys DA, DB) | P3 |
| conformity | D14, D24 | P2 |
| plausibility | D10, D25 | P3 |
| completeness | D18 | P4 |
| timeliness | D21 | P5 |
| uniqueness | D17 | P3 |
| accuracy | D22 | P3 |

## Run

```bash
# 1. Validate every oracle (0 rows on clean, >=1 on its trap)
python DQC/eval/eval_harness.py --selftest

# 2. Score a hand-written set of checks against the whole catalog
python DQC/eval/eval_harness.py --sql DQC/eval/example_checks.sql

# 3. Targeted eval against a running DQC agent (POST /dqc/generate)
python DQC/eval/eval_harness.py --agent http://localhost:8000/api

# 4. Materialise the databases to disk for ad-hoc inspection
python DQC/eval/generate_db.py --rows 2000

# JSON output for any mode
python DQC/eval/eval_harness.py --sql checks.sql --json
```

## Scoring (verifiable, no LLM judge)

Each candidate SQL gets the 5-component reward (mirrors
`training/dq/dq_reward.py`, weights sum to 1):

| Component | Weight | Meaning |
|---|---:|---|
| `r_parse` | 0.15 | SQLite `EXPLAIN` succeeds |
| `r_template` | 0.20 | SELECT + FROM + WHERE + correct table |
| `r_coherence` | 0.20 | WHERE references ≥ 2 columns (or a JOIN) |
| `r_clean_zero` | 0.20 | returns 0 rows on the clean DB (specificity) |
| `r_catches` | 0.25 | returns ≥ 1 row on the defect's trap (sensitivity) |

Aggregate metrics:
- **Precision** = fraction of supplied checks that are valid + clean.
- **Recall** = fraction of coherence (non-decoy) defects caught by some clean check.
- **Per-dimension recall** — any dimension below 50% is flagged `← DEFICIENT`,
  which is the signal that the agent/model is weak in that area (e.g. cannot
  write timeliness or conformity checks).
- **Decoy over-claim** — checks that fire on a single-column decoy should have
  scored `r_coherence = 0`; the harness counts these as a quality smell.

## Design notes

- The clean DB is generated by drawing consistent base attributes and
  re-applying the pipeline formulas, so *every* oracle returns 0 rows by
  construction. Each defect's `mutate(row)` then breaks exactly one invariant
  in a single appended row (fresh PK), so a non-empty result is unambiguously
  caused by that defect — the same mutation-testing contract as the RL reward.
- The harness is **self-contained**: `--selftest` and `--sql` need no LLM. The
  agent path is optional and degrades to the local scorer.
- Table aliases the agent emits (`mylib.ciclos_recuperacion`,
  `recuperatory_cycles`) are normalised to `ciclos_calibrados` before scoring.
