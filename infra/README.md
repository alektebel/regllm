# RegLLM AWS Infrastructure

Terraform modules for deploying RegLLM on AWS ECS Fargate.

## Architecture

```
Internet → ALB → ECS Fargate (regllm app)
                      │
          ┌───────────┼──────────────┐
          ▼           ▼              ▼
       RDS PG16    S3 Buckets      EFS
     (app + mlflow) (MLflow        (ChromaDB)
                    artifacts +
                    model weights)
```

## Prerequisites

- AWS CLI configured (`aws configure`)
- Terraform >= 1.7
- Docker (for building images)

## Bootstrap (one-time, before first `terraform init`)

```bash
# Create remote state bucket
aws s3 mb s3://regllm-terraform-state --region eu-west-1

# Create DynamoDB lock table
aws dynamodb create-table \
  --table-name regllm-terraform-locks \
  --attribute-definitions AttributeName=LockID,AttributeType=S \
  --key-schema AttributeName=LockID,KeyType=HASH \
  --billing-mode PAY_PER_REQUEST \
  --region eu-west-1
```

## Deploy

```bash
cd infra

# Initialize
terraform init

# Plan
terraform plan -var-file=environments/dev.tfvars

# Apply
terraform apply -var-file=environments/dev.tfvars
```

## After first apply: populate secrets

Secret *values* are never stored in Terraform. Populate them manually:

```bash
ENV=dev   # or prod

aws secretsmanager put-secret-value \
  --secret-id "regllm/${ENV}/groq_api_key" \
  --secret-string "gsk_..."

aws secretsmanager put-secret-value \
  --secret-id "regllm/${ENV}/hf_token" \
  --secret-string "hf_..."

# db_password is auto-generated by Terraform (random_password resource)
```

## Push Docker image to ECR

```bash
# Get ECR URL from Terraform output
ECR_URL=$(terraform output -raw ecr_repository_url)

# Authenticate
aws ecr get-login-password --region eu-west-1 | \
  docker login --username AWS --password-stdin "${ECR_URL}"

# Build and push
docker build -t regllm .
docker tag regllm:latest "${ECR_URL}:latest"
docker push "${ECR_URL}:latest"

# Force ECS to pick up the new image
aws ecs update-service \
  --cluster regllm-dev \
  --service regllm-app-dev \
  --force-new-deployment
```

## MLflow on AWS

The MLflow server is **not** deployed to ECS by this module — it is expected to run locally or on a separate instance. For production, set `MLFLOW_TRACKING_URI` in the ECS task environment to your MLflow server URL, and set `MLFLOW_ARTIFACT_ROOT` to `s3://regllm-mlflow-artifacts-prod/mlflow`.

To use S3 as the artifact backend when training:

```bash
export MLFLOW_TRACKING_URI=http://your-mlflow-server:5000
export MLFLOW_ARTIFACT_ROOT=s3://regllm-mlflow-artifacts-prod/mlflow
python scripts/train_combined.py --epochs 5
```

## Promote a model to Production

```bash
# List registered model versions
mlflow models list-versions --name regllm-lora-adapter

# Promote version N to Production
mlflow models transition-version \
  --name regllm-lora-adapter \
  --version N \
  --stage Production
```

## Destroy

```bash
terraform destroy -var-file=environments/dev.tfvars
```
